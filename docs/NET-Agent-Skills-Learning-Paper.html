1. What Are Agent Skills?

An agent skill is a reusable, task-focused instruction pack that teaches an AI coding assistant (GitHub Copilot, Claude Code, etc.) how to perform a specific developer task. Without skills, agents give generic advice and ask unnecessary follow-up questions. With skills, they follow structured workflows and produce production-ready results autonomously.

A skill is a directory containing a SKILL.md file with:

  • YAML frontmatter — name and description (for discovery)
  • Workflow steps — numbered, sequential instructions the agent follows
  • Validation checklist — how the agent verifies its own work
  • Common pitfalls — traps to avoid with specific solutions
Key Insight: Skills don't replace the model's intelligence — they provide domain-specific context the model doesn't already have. Think of them as a senior developer's checklist, not a tutorial.

3. Best Practices Primer

These principles come from the official skill authoring guide, adapted for .NET.

3.1 Be Concise

The context window is a shared resource. Only add information the model doesn't already know.

Ask yourselfIf "yes" → keep itIf "no" → cut it
Does the model need this explanation?✅❌
Can I assume the model knows this?❌ (remove)✅ (keep)
Does this paragraph justify its token cost?✅❌

3.2 Match Specificity to Risk

Freedom LevelWhen to UseExample
High (text)Multiple valid approachesCode review, refactoring
Medium (pseudocode)Preferred pattern, some variation OKTest scaffolding, report templates
Low (exact script)Fragile/critical operationsDB migrations, deployment scripts
Analogy: Narrow bridge with cliffs → exact instructions (low freedom). Open field → general direction (high freedom).

3.3 Structure & Progressive Disclosure

  • Keep SKILL.md under 500 lines
  • Split reference material into sibling files (REFERENCE.md, EXAMPLES.md)
  • References must be one level deep from SKILL.md (no chains)
  • Use a table of contents in reference files over 100 lines

3.4 Seven Rules at a Glance

#RuleBad ExampleGood Example

2Provide defaults"Use xUnit, NUnit, or MSTest""Use xUnit" (with NUnit escape hatch)
3Consistent terminologyMix "assembly", "DLL", "binary"Always "assembly"

6. How to Author a New Skill

Step-by-Step Workflow

  1. Identify the gap. Try the task with the agent without a skill. Document specific failures.
  2. Create test cases first. Write tests/<skill-name>/README.md (prompt), good.md (ideal behavior), bad.md (typical failure).
  3. Calibrate the rubric. Run the SkillEvaluator on good/bad to verify the rubric discriminates.
  4. Write minimal SKILL.md. Just enough to pass the gap from step 1. Don't over-document.
  5. Test with the agent. Load the skill and run the original prompt. Save the transcript.
  6. Evaluate. Run the SkillEvaluator on the saved transcript. Pass threshold: ≥ 0.75.
  7. Iterate. If the score is low, observe what the agent got wrong, refine the skill, re-evaluate.
  8. Submit a PR. Include the skill + test case. CI runs calibration automatically.

YAML Frontmatter Rules

FieldRules
nameMax 64 chars, lowercase + hyphens only, no reserved words (anthropic, claude)
descriptionMax 1024 chars, third person, includes what + when, no XML tags

Naming Convention

Use gerund form (verb + -ing):

✅ Good❌ Avoid
profiling-dotnet-appshelper
writing-xunit-testsutils
debugging-memory-leakstools

7. Testing Skills with LLM-as-a-Judge

The Challenge

Traditional unit tests verify code correctness. Skills produce behavioral outcomes from natural language — you can't regex-match "good agent behavior." LLM-as-a-Judge uses a separate, powerful LLM (Claude Opus 4.6) to evaluate whether an agent's behavior matches quality criteria.

Test Prompt  →  Agent + Skill  →  Transcript  →  LLM Judge  →  Score Card
                                                     ↑            (pass/fail)
                                        good.md + bad.md + rubric

Test Case Structure

tests/<skill-name>/
├── README.md       # Input prompt + success definition
├── good.md         # Expected behavior WITH the skill
└── bad.md          # Typical behavior WITHOUT the skill

The Universal Rubric (6 Criteria)

CriterionWeightWhat It Measures
Skill activation1.0Did the agent load the correct skill?
Tool usage2.0Did it use the right tools/commands?
Structured workflow2.0Did it follow systematic steps?
Actionable output2.0Is the output concrete and usable?
Completeness1.0Did it finish without loose ends?
No unnecessary questions1.0Did it proceed autonomously?

Scoring Formula

weighted_score = Σ(scorei × weighti) / Σ(weighti)

Each criterion is scored 0.0 (not met), 0.5 (partially met), or 1.0 (fully met). A skill passes if the weighted score ≥ 0.75.

Classification Matrix

Agent + Skill → GoodAgent + Skill → Bad
Agent alone → BadCORRECT (skill helps)INCORRECT (skill broken)
Agent alone → GoodINEFFECTIVE (skill unnecessary)REGRESSION (skill harmful)

8. The C# SkillEvaluator Tool

A .NET 8 console application in tests/SkillEvaluator/ that uses the GitHub Copilot SDK for LLM interactions. No separate API keys needed — it authenticates via the Copilot CLI.

Architecture

FileResponsibility
Program.csCLI commands: evaluate, calibrate, list, help
JudgeEvaluator.csCore: CopilotClient → LLM session → JSON scorecard parsing
TestCaseLoader.csDiscovers skills, loads README/good/bad, extracts prompts
Models.csTyped models: Rubric, EvaluationResult, CriterionScore

How It Works (Under the Hood)

  1. Creates a CopilotClient → starts the Copilot CLI server
  2. Opens a session with SystemMessageMode.Replace (pure JSON evaluator — no agent tools)
  3. Sends the rubric + good/bad references + candidate transcript as a single prompt
  4. Parses the returned JSON scorecard into typed EvaluationResult
  5. Reports pass/fail with per-criterion breakdowns

Commands

CommandWhat It Does
dotnet run -- listShow all discovered skill test cases
dotnet run -- calibrate --skill <name>Run judge on good.md & bad.md to verify rubric separation
dotnet run -- calibrate-allCalibrate every skill in one pass
dotnet run -- evaluate --skill <name> --transcript <path>Score a real transcript
dotnet run -- evaluate-all --transcripts-dir <dir>Batch-evaluate all transcripts
Getting Started:
copilot auth login → cd tests/SkillEvaluator → dotnet run -- list

9. Without vs. With Skills — Real Examples

Example: "My app keeps getting OOM-killed"

❌ Without Skill (bad.md)✅ With Skill (good.md)
  1. Agent gives 5-bullet generic advice list
  2. User asks "can you actually run diagnostic tools?"
  3. Agent installs dotnet-dump locally (wrong)
  4. Agent lists the dump, suggests "look for types from your namespace"
  5. User has to ask again for analysis
  6. ~9 minutes, 3 follow-ups, no root cause
  1. Agent loads debugging-memory-leaks skill
  2. Runs dotnet-counters monitor — confirms leak pattern
  3. Captures heap dump with dotnet-dump collect
  4. Runs dumpheap -stat — finds top type
  5. Traces with gcroot — identifies static ConcurrentDictionary
  6. Recommends MemoryCache with TTL
  7. ~90 seconds, 0 follow-ups, root cause + fix

Example: "Upgrade my .NET 6 project to .NET 8"

❌ Without Skill✅ With Skill
  • Updates only the main project, misses test project
  • Doesn't update NuGet packages
  • Doesn't run tests after migration
  • Leaves warnings unaddressed
  • Scans all .csproj files, updates both
  • Checks dotnet list package --outdated and upgrades
  • Builds, runs tests, verifies 0 errors
  • Produces a summary table of all changes

10. How to Contribute

Quick Checklist

  1. Search existing issues/PRs to avoid duplicates
  2. Open an issue before submitting a PR for new skills
  3. One skill per PR
  4. Include a test case (README.md + good.md + bad.md)
  5. Run dotnet run -- calibrate --skill <name> to verify rubric separation
  6. Follow the YAML frontmatter rules (lowercase, hyphens, ≤64 chars)

What We Look For

✅ Likely to Accept❌ Likely to Decline
Narrow scope, easy to reviewBroad frameworks or large reorganizations
Motivated by a real use caseDuplicate of existing skill
Includes validation stepsContains private environment details
Verifiable by a reviewerDepends on proprietary tools
